Laravel框架chunkbyId的使用

Oct 29, 2024
阅读时长: 2 分钟

#Laravel的chunk的介绍

chunk 方法用于将大型集合分成小的块进行处理。这对于处理大量数据时非常有用，因为它可以节省内存并提高性能。

  • 内存优化: chunk 和 chunkById 方法在处理大量数据时非常有用，因为它们只在内存中保留当前块的数据，而不是整个数据集。
  • 数据一致性: 在使用 chunkById 时，确保数据表的主键没有被删除或修改，以避免漏掉数据。
  • 性能: 使用 chunk 方法时，可能会对数据库产生多次查询，因此要根据实际情况评估性能。

#Laravel的chunkId介绍

先看一下laravel的源码

    public function chunkById($count, callable $callback, $column = null, $alias = null)
    {
        $column ??= $this->defaultKeyName();

        $alias ??= $column;

        $lastId = null;

        $page = 1;

        do {
            $clone = clone $this;
            
            $results = $clone->forPageAfterId($count, $lastId, $column)->get();

            $countResults = $results->count();

            if ($countResults == 0) {
                break;
            }

            if ($callback($results, $page) === false) {
                return false;
            }

            $lastId = data_get($results->last(), $alias);

            if ($lastId === null) {
                throw new RuntimeException("The chunkById operation was aborted because the [{$alias}] column is not present in the query result.");
            }

            unset($results);

            $page++;
        } while ($countResults == $count);

        return true;
    }

默认使用连接里面的主键，它在处理大数据集时更有效，尤其是在有主键的情况下。它使用主键进行分页，避免了可能的重复数据问题。但是使用时候还是要注意，排序不一定生效，已经使用的字段是非主键的情况下：看看chunkById里，result的源码

    public function forPageAfterId($perPage = 15, $lastId = 0, $column = 'id')
    {
        $this->orders = $this->removeExistingOrdersFor($column);

        if (! is_null($lastId)) {
            $this->where($column, '>', $lastId);
        }

        return $this->orderBy($column, 'asc')
                    ->limit($perPage);
    }

获取结果集的时候，内部使用的主键或者是调用时候自定义的键，但是限制条件是’>’,所以一些字符串的使用可能不太恰当，同时默认采用了升序，降序的话，可能达不到效果😯；最后，如果你使用的sql是组合sql,类似union,那么

$this->where($column, '>', $lastId);

这个限制条件可能不会在每个子sql里面

因此在使用chunkById时候，要注意实际的业务需求考虑。
